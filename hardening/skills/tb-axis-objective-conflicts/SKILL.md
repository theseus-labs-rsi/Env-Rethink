# 轴③ 目标冲突（conflicting objectives）

**加的是什么难度**：两条（或更多）**都合法**的标准在同一处冲突，不存在"都满足"的解；必须做取舍，并把**取舍依据写进产物**（留痕本身是判分项）。读得再全也躲不掉判断。

## 1. 一眼假 vs 真实难度（硬对照）

| 维度 | ✗ 一眼假（禁止） | ✓ 真实难度（要求） |
| --- | --- | --- |
| 标准的数量 | 只是把分数拆细（加权更多项） —— 标准变多 ≠ 变难 | 标准**互相冲突**：满足 A 必然牺牲 B |
| 可两全性 | 存在一个解同时满足全部标准 | **数学上不可两全**（两条标准的最优解不同，必须选一个） |
| 依据 | 冲突靠"感觉"（判分无法核对） | 冲突双方都有**文本依据**（两个部门的口径、两条 SOP、两个来源族），可被独立复核 |
| 留痕 | 只要求"做出决定" | 要求写出**为什么这样取舍 + 引用了哪条证据**；不写 → 掉分 |
| 与判分的关系 | 冲突不影响判分（写不写都一样） | 判分**分别检查**：① 取舍结果正确；② 留痕里有依据引用 |

**一句话检验**：如果两个标准能被同一个答案同时满足 → 不是冲突，重做。

## 2. 现成的冲突模板（本项目已验证可判的）

1. **精度 vs 完整性**（种子题已有雏形）：一部分条目证据不足以判定 → 交（可能错）还是不交（不完整）。判分同时看"交了什么"与"扣下了什么、为什么"。
2. **口径 A vs 口径 B**：两个部门（财务 / 合规）各自的口径文件都在，都"有权"；SOP 只给优先级原则，具体到某条记录必须自己判，并在 memo 里写明采用了哪一口径、依据哪条。
3. **时间边界冲突**：跨期条目 —— 按"物理过境"与按"入账月份"分别落在不同期间；两条规则都在，必须选一条并说明。
4. **来源等级冲突**：更权威但更旧 vs 更具体但更晚（本项目的批次台账 vs 合同参考价就是这类）。

## 3. 手法：把"取舍依据"做成检查项

- 在产物 schema 里**加字段**（例如 memo 的 `conflict_rulings: [{field, chosen_source, evidence_ref, why}]`）；
- 判分侧对每个冲突点检查三件事：**选对了**（结果）、**引用了正确依据**（引用）、**没有把另一个口径混进来**（负向检查）；
- 冲突点数量 ≥2（1 个容易蒙）；每个冲突点独立可判（互不依赖）。

## 3.5 决定性判定点（R4 起强制，≥3 个）

R3 实测教训：只写"两条标准冲突、请取舍"不构成难度 —— 模型按**看起来更权威的那条**随手选一个，选对了不涨难度、选错了才是难度。**每个冲突点都要有吸引子：把"更显眼的那条标准给出的具体值"写进环境，让默认解法必然产出它。**

- 默认解法（照最正式/最新的那份办）→ 吸引子：具体错值；
- 按正确的冲突裁定 → 唯一正确值，且裁定依据必须留痕（进判分）；
- ≥3 个冲突点（可以是"一条裁定规则 × 多个字段"）；写进 `plan.yaml` 的 `decisive_points:`，`default_answer` 写"模型会选哪条标准、输出什么值"。

## 4. 产出要求（写进 `plan.yaml`）

```yaml
axis: objective_conflicts
conflicts:
  - pair: [<标准A>, <标准B>]
    site: <哪条记录/哪个字段>
    evidence_a: <文件+定位>
    evidence_b: <文件+定位>
    correct_choice: A|B
    why_required: true          # 留痕是否进入判分
    checks: [result, citation, negative]
memo_justification_required: true
```

## 5. 自检（必须全过）

1. **不可两全**：把参考解的两种选择各跑一次 → 判分**只有一个能过**（证明冲突真实存在）。
2. **留痕可判**：删掉留痕字段 → 掉分（证明它真的被检查，而不是装饰）。
3. **依据可复核**：冲突双方的依据都能被独立复核者用文本证据判定（不靠外部知识）。
4. **不污染其它检查**：新增冲突点不得让原有检查变松（逐项 diff 判分器改动）。
5. **判据**：跑批后失败集中在"取舍/引用"类检查 —— 模型答"两个都写"或"选错"都应掉分。
