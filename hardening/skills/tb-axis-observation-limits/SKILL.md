# 轴② 观测受限（observation limits）

**加的是什么难度**：不靠"文件更多"，靠**物理上看不全时的决策** —— 总量超出观测额度、关键行不在默认视图、换视图要付出代价。长上下文也抹不平，因为信息确实没给。

## 1. 一眼假 vs 真实难度（硬对照）

| 维度 | ✗ 一眼假（禁止） | ✓ 真实难度（要求） |
| --- | --- | --- |
| "藏"的方式 | 把关键行埋在超长文本中间（`grep`/`rg` 一下就出来） | 关键行**根本不在默认视图**：要翻页、换过滤器、打开附件才能看到 |
| 可绕过性 | 同一事实在别处重复出现（绕开限制也能拿到） | 关键事实**只在一处**，且拿到它必须消耗额度/翻页 |
| 代价 | 无代价（想看多少看多少） | 每次观测**有成本**（条数上限、时间、必须留痕），必须规划观测顺序 |
| 与判分的关系 | 观测不到也不影响判定（看了也白看） | **不观测就必然判错**（判分恰好检查需要那一行的字段） |

**一句话检验**：如果模型用一次 `grep`/一次全量读就能拿到关键事实 → 这不是观测受限，是检索题，重做。

## 2. 手法清单（选 1–2 个，不要全上）

1. **分页 / 游标**：服务接口每页最多 N 条，关键记录在第 3–5 页；游标是单向的（不能跳页）。
2. **额度（quota）**：接口按"返回行数"计费/限流，全量拉取必然超限 → 必须先用别的视图缩小范围。
3. **视图受限**：文件只有图片/PDF/表格视图；工具默认给前 N 页或缩略图，关键数字在第 2 页 —— 要显式翻页并把观察写进产物。
4. **附件必须显式打开**：事实写在附件里，接口只给附件名与大小。
5. **观测留痕**：memo / 报告里必须写出"在哪一页/哪一次查询看到了什么"（让"没观测到"无法蒙混）。

## 2.5 决定性判定点（R4 起强制，≥3 个）

R3 实测教训：只让"多翻几页"不构成难度 —— 模型翻了页、照样做对。**每个观测受限点都要有吸引子：默认视图里摆着一个具体的错值，不看关键页就会把它抄走。**

- 默认视图（第 1 页 / 缩略图 / 前 N 行）→ 吸引子：一个具体、合理、看起来是终值的错数（例如"更正前"的那一版、被撤回批次的总数）；
- 翻到关键页 + 结合别的面 → 唯一正确值；
- ≥3 个这样的点；写进 `plan.yaml` 的 `decisive_points:`，`attractor_location` 写清"默认视图里的哪一行"。

## 3. 产出要求（写进 `plan.yaml`）

```yaml
axis: observation_limits
surfaces:
  - {name: <接口/文件>, kind: pagination|quota|view|attachment, limit: <N>, required_fact: <关键事实>}
visible_ratio: 0.2        # 默认视图能看到的事实占比（越小越受限）
pages_required: 3         # 拿到全部关键事实至少要翻几次/几次查询
strategy_required: true   # 是否存在"聪明做法"（先缩小范围再取）——必须存在，否则是运气题
```

## 4. 自检（必须全过）

1. **额度/视图真的生效**：用同一提示直连一次 → 默认视图下**拿不到**关键事实（有命令输出为证）。
2. **不观测就判错**：判分的对应检查恰好依赖那一行；漏看 → 掉分，且失败类型是"误判"而不是"超时"。
3. **策略可解**：存在一条"先用便宜视图缩小范围，再花额度取关键行"的解法 —— 由参考解在限额下跑通验证（额度用满即失败）。
4. **无重复泄底**：关键事实在别处（其它文件/其它接口）不得出现。
5. **判据**：给足额度时不掉分、给紧额度时掉分（额度对照）。
