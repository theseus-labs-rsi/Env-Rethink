# 轴① 跨面裁决（cross-surface adjudication）

**加的是什么难度**：判定"哪一版有效"必须跨两条面才能做对；**只看任一条面都会得出错结论**（注意：是"错"，不是"不确定"）。打的是来源选择能力，不是阅读量 —— 所以不会像"堆文件"那样饱和。

## 1. 一眼假 vs 真实难度（硬对照）

| 维度 | ✗ 一眼假（禁止） | ✓ 真实难度（要求） |
| --- | --- | --- |
| 免责声明 | 诱饵自带 "indicative / 仅供参考 / 非官方 / 内部草稿" | **零免责句**；诱饵的措辞与正本一样正式 |
| 与真相的时间 | 诱饵比更正**旧**（读日期即可排除） | **晚于**更正，并**主动声称**对本期生效 |
| 取值 | 第三个数字（对不上任何来源） | **旧值**；与未更正的旧件构成**互相印证**（两处旧值 vs 一处新值） |
| 主体类别 | 外部商业供应商（与治理源不同类，一眼归错） | 与治理源**同类别**（内部口径确认、兄弟系统、官方镜像） |
| 排除依据位置 | 写在诱饵自己身上，或写在**含答案的那份文件**里 | 移到**另一条面**：登记册 / 审批流 / 审计记录 / 另一来源族 |
| 规则形态 | 规则直接给结论（"以更正为准"） | **规则条件化**：规则只给条件，裁决数据在服务面 |

**一句话检验**：把诱饵和正本放一起，如果"为什么假"能只靠读这两个文件看出来 → 失败，重做。

## 1.5 数值面：错值要具体，正解要"算得出、读不到"（2026-09-16 实测教训）

**背景（踩过的坑）**：第一版变体把**正确值直接列进了登记册**（`new_value = 9400.00`），结果在弱模型上**变体比原题还容易** —— 原题要读合同附件推导 900.00，变体改成照表抄。加难绝不能降低目标项的推理成本。

| 规则 | ✗ 禁止 | ✓ 要求 |
| --- | --- | --- |
| **正解的可读性** | 正确值出现在任何一份可读的表/记录里（登记册、确认件、台账直接列 new_value） | 正确值**只能算出来**：变体里所有文件都不得直接给出目标字段的正确数值；给出的是"依据"（单价×数量、比例、口径），推导链必须与原题**同长或更长** |
| **错值的具体度** | 诱饵只说"沿用旧值/以 X 为准"（没有数字） | 诱饵**必须带一个具体错值**：一个看起来权威、数值合理的错数（如伪登记记录的 `new_value`、伪确认件的"已核定单价"），让偷懒的模型有东西可抄 |
| **错值的可信度** | 错值离谱（与任何来源都对不上、或明显异常） | 错值要**落在合理区间**（与正确值同量级、差额可解释为口径差异），且出现在**看起来最该信的位置**（正式表格/已受理记录/确认件） |
| **对称性** | 正解在明面、错值在暗处 | 两者都摆在明面上：**错值更显眼（有具体数），正解更费劲（要跨面核验 + 推导）** |

**自检（必须全做）**

1. **正解不可读**：把变体全部文件里出现的数值列出来（`grep` 目标字段 + 数字），确认**没有一处**等于正确值（或可直接换算成正确值）。
2. **错值有具体数**：每条诱饵都能指出"它给的错值是多少"，且该值能被模型原样抄进产物（错误可检测）。
3. **推理成本对照**：同一目标项，在种子上的判定链（找依据 → 推导）与变体上的判定链相比**不得更短**；记录两者步数，写进 `plan.yaml` 的 `reasoning_cost`。
4. **可解性**：正确值确实能从环境推出（跨面核验后 + 依据推导），参考解在**新环境**下算出的值 == 新 expected。

## 2. 手法：规则条件化（本轴的核心）
规则页（SOP / 说明）**不要**下结论，写成条件句，把裁决权外移：

> 若 X 在登记册中已登记（登记号以 `REG-` 开头），则 X 优先于 Y；否则以 Y 为准。

于是：
- 光看工区文件 → 只能看到 X（晚于 Y、措辞更正式、值为旧值）→ **会判错**；
- 只有去服务面查登记册 → 发现该登记号不存在 / 已被驳回 → 才回到 Y。

落点（工区）与服务面（必须核验的事实）分列：

| 工区看得见 | 服务面才看得见 |
| --- | --- |
| 晚于更正的"口径确认"件（同类别措辞） | 登记册里**查无此登记号**（或状态=撤回/驳回） |
| 与旧件一致的旧值 | 服务返回的 `correctionOf` provenance |
| 条件化规则页 | 审批流的最后一条记录 |

## 2.5 决定性判定点（R4 起强制，≥3 个）

R3 实测教训：跨面材料如果只是"加了一层要查的东西"，模型查完照样做对 → 难度不起作用。**每个跨面裁决点都必须是反默认的，且单面路径要给出一个具体错值。**

- 单面（只看工区）→ 落进吸引子：**具体的错值/错行为**（照抄旧值、按通用口径归一、把该缺报的报出来），不是"判不出来"；
- 跨面（工区 + 服务记录）→ 唯一正确值；
- ≥3 个这样的点，各自独立（不要三个点其实是同一条规则的三次重复，除非"一条规则 × 多个判分项"本身就是设计目标）。

写进 `plan.yaml` 的 `decisive_points:`（格式见主 skill §4），其中 `attractor_location` 指向"单面路径会照抄的那份文件与行"。

## 3. 产出要求（写进 `plan.yaml`）

```yaml
axis: cross_surface
cross_surface_sites: 1          # 需要跨面裁决的判定位点数（≥1）
decoys:
  - class: hijack_final          # 或 fabricated_authority / redirect
    path_slot: version-chain end # 挂在事件路径的哪个位置
    artifact: <工区路径>
    service_surface: <服务接口/记录>   # 反驳它必须查的那条面
    refutation_evidence:         # ≥2 项，且至少一项来自另一条面
      - {surface: workspace, detail: "..."}
      - {surface: service,   detail: "..."}
    self_negating: false         # 必须为 false
```

## 4. 自检（必须全过）

1. **单面截断**：把服务面藏掉只留工区 → 期望**判错**（不是"不确定"）；再藏工区只留服务面 → 同样判错。做到这一步才算跨面。
2. **无自否定**：`grep -iE "superseded|仅供参考|indicative|not official|草稿|作废"` 在诱饵里**零命中**。
3. **答案文件不自带排除理由**：含正确答案的文件里不得出现"不要用 X / X 不适用"这类替模型做判断的句子。
4. **可解性**：正本可达、唯一有效状态可恢复（登记册这一面必须真的能查到"没有这个号"）。
5. **判据**：跑批后失败集中在判定类检查（如版本/权威选择），而不是"没做完"。
