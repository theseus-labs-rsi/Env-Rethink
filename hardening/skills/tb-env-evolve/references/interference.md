# 干扰类型参考（noise-id 分类法）

来源：`Workspace-Bench/evaluation/docs/noise_id_v2t_model_report.md`（noise-id v2t 报告）。设计环境干扰时**直接复用这套分类**，不要自造。

## 6 类噪声（内在机制）

| 类别 | 含义 | 识别特征 |
| --- | --- | --- |
| `canonical` | **正本**（不是噪声，是目标） | 权威、完整、内部一致；被登记/锁档链指向 |
| `hijack_final` | **伪终版劫持**：自称 final / 最新，但与真实版本链或自身矛盾 | `_final` / `最终版` / `当前数据包` 命名 + 内部不一致 |
| `fabricated_authority` | **伪造权威证据**：成套 FINAL/APPROVED 包、伪造审批/邮件/群聊佐证 | 审批链无对应登记；成套权威标记但数据孤立；跨表矛盾 |
| `redirect` | **指令劫持**：说明文本指示弃用正本改用他源 | "正本有误" + 时间线矛盾 |
| `superseded` | **被取代版本**：草稿 / 待确认 / 复核 / 外发副本 / 归档 / 作废 / 旧年度 | 显式状态标记（文件名或版本说明） |
| `unrelated` | **无关文档**：工作区里其他主题的正常文档 | 与核心主题无关 |

核心行为：**stage ≠ 事实**。文件可以自称 final / archived / voided（stage），核验后的判定才是真值 —— 要考的就是"不轻信标记、标记必须核验"。

## 4 类语义单元（组合原子，成套在场）

| 单元 | 定义 |
| --- | --- |
| **攻击场景** | 诱饵链完整成员（伪终版 / 伪权威包 / 审批件 / 支持文本）+ 其攻击目标正本 |
| **版本族** | 正本 + 同族被取代版本（含先后顺序链） |
| **指针 / 诱导组** | redirect 文本、快捷方式、邮件、群聊导出 |
| **bulk 组** | 状态标记单例、无关文档，按目录或类型分组 |

## 硬规则（场景完整性）

1. 攻击场景**必须包含攻击目标正本** —— 否则"找正本"无解；
2. 诱饵与其支持文本 / 审批件 / 回声件**成套出场**，不拆散证据链；
3. 版本族**优先整族出场**（顺序链完整，才能判时间线）；
4. bulk **只做填充**，不单独构成结构；
5. 正本数量随批次自然变化，避免"恒定恰好一个正本"的捷径先验。

规模三档（供参考）：S 4–12 文件 / M 12–30 / L 30–80。

## 失效边界

**多源互相印证**（多个伪造件互相引用，正本 0 存活）会打穿"唯一有效状态可恢复"。要叠这类干扰时，必须同时给出打破这条印证链的证据（登记记录、时间锚），否则就是出废题。

## 在事件日志里怎么挂

每条干扰都要能指到"题面 → 有效材料"这条链上的**位置**，不能只堆文件：

| 类别 | 挂在路径的哪里 |
| --- | --- |
| `superseded` | 版本链的中间节点（原版留在原位） |
| `hijack_final` | 版本链**末端**（插一个"更新"的版本） |
| `fabricated_authority` | `derived_from` 链上插一条伪造的更正 / 审批事件及其成套附件 |
| `redirect` | 规则类材料（SOP / README / 交接说明） |
| `unrelated` | 任意位置，bulk 填充（只作对照档） |
| `canonical` | 链条终点，必须可达 |
