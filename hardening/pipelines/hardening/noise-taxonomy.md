# 噪声注入规格（TB 版）

> **来源**：六类噪声的定义与实测分布，来自作者另一个 benchmark 项目的标注 taxonomy；
> 与 TB 自己的干扰四类（`skills/tb-env-evolve/references/interference.md`）合并后的**可移植层**。
> 该项目专有的部分（输入角色真值、办公文件形态、审批流面）不搬，映射见 §5。
>
> **一句话**：噪声必须**看起来是真的**（能骗过最省力路径），但**能只靠题面 + 环境里的可见内容排除**
> —— 排除依据要么在文件内容里（自相矛盾 / 时间倒挂 / 与正本数值冲突），要么靠跨文件比对；
> **绝不允许靠文件名自曝**（"旧版/错误/损坏/不要用"）或靠隐藏标记排除。

---

## 1. 两类记账（每一份新材料都要落一项）

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `partition` | `canonical` / `noise` | 正本之外的**全部**材料都算噪声（包括"正常但无关"的文档） |
| `category` | 见 §2（6 值） | 噪声的类型 |
| `stage` | 见 §3（10 值 + null） | **这份材料自己声称**处于什么状态，与"它事实是什么"无关 |

`stage ≠ category` 是这套规格最容易写错的地方：

- 文件名 `final_v8.csv` → `stage: final`（它自称）、`category: hijack_final`（它是伪终版）
- 一份自称"草稿"、但其实是本题唯一数据来源的文件 → `stage: draft`、`category: canonical`

---

## 2. `category` 六类（全量，不许自造）

| category | 定义 | 判定依据（必须能说清） |
| --- | --- | --- |
| `canonical` | **正本**：权威、完整、内部一致 | 本题要交的答案只能从它推出 |
| `hijack_final` | **伪终版**：自称 final / 最新 / V7 / 当前口径，但与真实版本链或自身矛盾 | 与正本**比对**：命名冒充终版，内容却是正本的删节本 / 被改过的版本 |
| `fabricated_authority` | **伪权威**：成套 `FINAL` / `APPROVED` / 已核定 / 会签 / 校验和 装饰，但没有对应的登记 / 溯源支撑 | 与正本比对**"它凭什么有权"**：编号查无登记、上游产物不存在、平行包越权 |
| `redirect` | **指令劫持**：说明件（README / 说明 / 索引 / 备注）声称正本有误、指示改用别的来源 | 指令性散文 + 声称正本有误 + 与时间线矛盾 |
| `superseded` | **被取代版本**：真实但非正本，带显式状态标记（草稿 / 旧版 / 归档 / 作废 / 待确认 / 上一年度） | 有状态标记，且与正本构成版本族（见 §4） |
| `unrelated` | **无关文档**：环境里**其他主题/对象**的正常文档 | 同域不同职能，与正本口径无冲突 |

**强诱饵 vs 填充**（配比按这个来）：

- **强诱饵**（必须 ≥1 类，且必须给具体错值、必须能被另一条证据反驳）：`hijack_final` / `fabricated_authority` / `redirect`。
- **填充**（只加密度，不单独构成结构，**不得**当判定点的吸引子）：`superseded` / `unrelated`。

> ⚠️ 这两类的判据本身**依赖显式状态标记**（"初稿/归档/已作废/待确认"），而 TB 侧明令**诱饵不得携带自否定标记**
> （`skills/tb-axis-cross-surface/SKILL.md:87`：`grep -iE "superseded|仅供参考|indicative|not official|草稿|作废"` 在诱饵里必须零命中）。
> 所以搬运时**只能把 superseded/unrelated 当 bulk 填充**；要当诱饵必须剥掉状态标记，改由"另一条证据"来反驳
> —— 那就已经变成 `hijack_final` 了。这条冲突是 WB 与 TB 两边规格的唯一直接冲突，取舍如上。

**分界（写错就废）**：

- `hijack_final` vs `fabricated_authority`：矛盾在**内容值**（数字/日期/字段对不上）→ `hijack_final`；
  矛盾在**它凭什么有权**（登记/编号/上游产物不存在）→ `fabricated_authority`；两者都成立 → 判后者。
- 带 `FINAL` / `APPROVED` 且与正本冲突的，**不许**因为"反正它是噪声"就降级成 `superseded` 或 `unrelated`
  —— 降级会把最强的诱饵白送掉（WB 实测：本管线重标后 `hijack_final` 从 1 升到 79，`unrelated` 从 252 降到 121）。
- `unrelated` 只能是**其他主题**；同主题的干扰项一律归 §2 前五类。一个任务里 `unrelated`
  **不得超过噪声文件数的 60%**。

## 3. `stage` 十值（自称状态，不许自造，不许发明 `archived_old` 这类词）

```
draft | pending | in_review | final | external_copy | archived | voided | outdated | canonical | null
```

落点：文件名或正文里的显式标记（`_V7`、`-final`、`草稿`、`待确认`、`已作废`、`归档1`、`副本`）。

---

## 4. 版本族（`family`）：噪声的骨架

单一诱饵是弱信号；**版本族**才是可排除性的来源。每一族记：

```
family_id: F1
subject:   <这一族讲的是哪个对象/文档>
members:   [ {path, stage, date, order}, ... ]      # 真实时间线，order 递增
canonical: <族内正本的 path>
fabricated_members: [ {path, claimed_stage, contradiction: "<与正本的可见冲突>"} ]   # 伪件单独列出，不进时间线
```

硬规则：

1. **整族出场** —— 只放一个孤零零的伪终版，agent 一眼就知道是异物；正本 + 前代 + 归档 + 伪件同族在场才算"版本链"。
2. **伪造成员必须写得出 `contradiction`** —— 矛盾点要能在**文件内容**里指出来（不是"它名字像假的"）。
3. `date_anchor`（`YYYY-MM-DD`）从版本说明 / 审批日期 / 正文里提取，无则 null；**时间倒挂**是最强的可移植排除依据。

## 5. 落到 TB 形态的映射（没有服务面怎么办）

TB 题目是单容器文件树，没有 iWiki/wecom 那种服务面。映射规则：

| taxonomy 类 | TB 里的载体（盘面 = `/app/**`，材料面 = `environment/**` 与构建期产物） |
| --- | --- |
| `canonical` | 题面指定的输入文件本身（**不得改动它的语义**） |
| `hijack_final` | 同族的"更新版"：`*_final.csv`、`*_v7.jsonl`、被删节的日志切片、只覆盖部分窗口的导出 |
| `fabricated_authority` | 带校验和/签名/CI 装饰的产物：`manifest.sha256`、`*.stamp`、`release/`、`build/reports/`、被 `APPROVED` 标记的清单 —— **其声称的来源在环境里不存在** |
| `redirect` | `README` / `NOTES.md` / `TODO` / `runbook` / 注释：声称某文件已作废、指示改用另一份 |
| `superseded` | `archive/`、`*.bak`、`old/`、`draft/`、`2024/` 等目录里的真实前代 |
| `unrelated` | 同域不同职能的正常文件：别的服务的日志、别的批次的报表、**和本题无关但格式一致**的 `summary.csv` |

**"权威"在 TB 里重新定义**（WB 的判据绑审批/登记，搬不过来）：TB 的可信度来源是
**构建期产物（Dockerfile 里 RUN 出来的东西）> 运行时目录 > 说明文档**，
以及**能否自洽复算**（校验和、行数、时间窗）。伪造权威 = 一份自称由构建期产生、
但校验和/行数/窗口与真实产物对不上的文件。

## 6. 允许 vs 禁止（这条界线是整套规格的底线）

✅ **允许、且鼓励的迷惑性**：

- 伪终版、伪权威包、删节本、改名近副本、机械改写、多源互相印证网；
- 针对 agent 最可能的搜索/读取方式做针对性规避（例如让 `grep` 命中一个错值）；
- 正本**不自带**"验证策略"以外的帮助；诱饵**成套出场**。

❌ **禁止的自我暴露**（违反即废）：

- 文件名或正文里出现 `错误版 / 旧版 / 过期 / 损坏 / 不要使用 / DO NOT USE` 这类**一眼假**的词；
- 诱饵自带免责声明（`superseded / indicative / 仅供参考 / 非官方 / 草稿（其实不是）`）；
- **排除依据只存在于文件名里**，文件内容看不出任何毛病；
- 两个版本在**可见证据上同样合理**（→ 题目变成不可判）。

> WB 验收侧的原话（`evaluation/scripts/noise/prompts.py:200-211`）：噪声"只能在依赖隐藏答案或内部标记才能排除"的，
> 一律打回；"只有当 `exclusion_reason` 描述了内容层面的差异（日期、周期、数值、范围）而字节并未改变"才算问题。

## 7. 与「反默认判定点」的关系（噪声不是自娱自乐）

每一类噪声都必须挂到一条**判定点**上，否则只是阅读量（TB 实测：新增面不构成难度）：

```
noise → 默认路径（最省力）→ 具体错值 → 判定点 → 判分项
```

- **诱饵必须给具体错值**：不是"沿用旧值"这种没数字的暗示，而是与正确值**同量级的具体数**
  （放在看起来最该信的位置），让偷懒的模型有东西可抄、抄了就错。
- **错值要显眼、正解要费劲**：错值摆在明面上且有具体数；正解必须跨文件核验 + 推导。
- 每条判定点在 `plan.yaml:decisive_points` 里写全六格（`question / default_answer / correct_answer /
  attractor_location / scored_check / why_default_is_wrong`），`attractor_location` 里
  `default_answer` 的具体数字必须能在该文件正文里 grep 到（`tools/gate_check.py` 机械核对）。

## 8. 不泄漏答案的三道机械自检（每轮交付前必跑）

1. **断言值 grep** —— 用了 `answers-digest.md` 抽出的断言常量，逐个 grep 本轮新增材料；命中即改（`case:` 类判分常量同理）。
2. **对象黑名单 grep** —— 原题要交的目标对象（文件名 / ID / 字段）不得在本轮新增材料里被"点名否定"或"直接给出"。
3. **材料作用域表**（结构化，不再只是散文）—— 逐条判分检查回答三问：
   「我的哪份材料可能帮到它 / 为什么不会（只谈新增对象）/ 我的材料唯一的效力范围」。

> 实测教训（TB 81 个变体里只有 3 个真交了作用域表）：**否定式结论同样是答案**
> （"少了一条记录 → 所以不用算"这种话就是泄漏）。多代累积后泄漏面只会变大，所以作用域表必须逐代写、逐代查。
