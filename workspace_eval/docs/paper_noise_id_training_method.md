# 面向多模态噪声工作区的任务无关噪声识别：子环境构建与后训练方法

> 说明：本文档面向论文写作，描述"噪声识别模型"的技术方案——从数据、标注、子环境构建、
> 教师轨迹（rollout）到后训练与评估。避免具体实现细节，只保留方法层面的设计。

## 1. 问题背景与任务定义

办公类智能体（Agent）常面对**大规模、异构、且存在显式/隐式依赖的工作区**。任务文件并不总是
可信：工作区中同时存在多版本文件、伪造的"最终版"、仿造的审批/权威链、过期副本以及大量无关文档。
我们把"文件本身是否可信、处于哪一版本、属于哪一伪造类别"定义为**文件的内在噪声属性**——它不依赖
具体任务文本即可判定。

据此定义**任务无关的噪声识别任务**：输入为一组文件（无任务描述），输出三件事——
1. **划分**：每份文件是 `standard`（可信正本）还是 `noise`；
2. **噪声类别**：每份噪声文件属于哪一类内在类别；
3. **时间线**：对存在多版本的文档族，给出成员阶段、日期锚点与先后顺序；对伪造链，指出其声称
   的权威时间线与真实记录的矛盾。

模型定位：**工作区内容过滤/校验模块**，在 Agent 阅读文件前把噪声与正本分开，降低 Agent 被
伪权威、伪终版误导的概率。该模块以离线文本与（必要时）OCR 文本为输入，判断独立于任务。

## 2. 数据：噪声敏感任务集与逐文件标签

### 2.1 任务筛选
从困难任务集 `tasks_hard_v4`（30 个任务、1280 条 rubric）中，依据同一组模型在 clean/noise 两种
条件下的得分差筛选"噪声敏感"任务：要求 clean 基线高（≥90%）、加噪后显著下降（-38pp ~ -75pp）、
且噪声机制可被文件内在证据解释（版本劫持、来源伪造、过期/无关填充）。

最终得到 12 个核心任务（后勤/运营，合计 1235 个文件），并标注 4 个备用任务（覆盖研究/开发角色等）
作为扩充储备；共 **16 个任务、1597 个文件**进入训练数据池。

### 2.2 标签体系
- **partition**：`standard`（可信正本）与 `noise`（其余全部）。语义约定：正本之外即噪声——部署目标是
  "工作区过滤"，模型应学会把无关但与正本共存的正常文档也判为噪声（其类别为 `unrelated`）。
- **category（6 类，内在、可核验）**：
  | 类别 | 含义 | 典型识别特征 |
  |---|---|---|
  | canonical | 正本：权威、完整、内部一致 | 移交批次/综合档案路径、锁档链指向、完整源数据 |
  | hijack_final | 伪终版劫持：自称 final/最新，但与真实链或自身矛盾 | `_final/最终版` 命名 + 内部冲突 |
  | fabricated_authority | 伪造权威证据：成套 FINAL/APPROVED/审批/邮件/群聊佐证 | 审批无登记支撑、跨表孤立 |
  | redirect | 指令劫持：README/口径说明指示改用他源 | 声称正本有误 + 时间线矛盾 |
  | superseded | 被取代版本：草稿/待确认/复核/外发/归档/作废/旧年度 | 显式状态标记 |
  | unrelated | 无关文档 | 与目标主题无关 |
- **stage（观测标记，与 category 分离）**：记录文件"自称"处于什么状态（草稿/最终/已归档…）。**标记≠事实**：
  例如一份文件自称 `final`（stage），经过核验实为伪造终版（category=hijack_final）。stage/category 分离是
  教学重点：模型须学会"不轻信标记，标记需核验"。
- **family/时间线**：把同一对象的多版本/伪链组织为族，记录成员阶段、日期锚点、顺序与伪造成员的矛盾证据。

### 2.3 标注流程（质量与效率）
采用"分层 + 人工兜底"的流水线，避免对全部文件做昂贵内容级标注：
1. **规则层**：文件名/路径状态标记与 partition 硬约束，先给大部分文件高置信的 stage 与
   superseded/unrelated 预判；
2. **报告层**：把逐任务深度分析报告中的诱饵排除证据直接转写为强诱饵类别（hijack_final /
   fabricated_authority / redirect），并据此组织 family/版本链——这是标签质量的上限来源；
3. **LLM 层**：对规则/报告未覆盖的文件（多为 bulk 内容级判读）由教师模型盲标；
4. **交叉校验 + 人工复核**：partition 与 manifest 零冲突、类别枚举合法、族内一致性断言；对全部
   强诱饵与分歧文件人工终审，其余按类别分层抽样复核。

最终 1597 个文件均有（partition, category, stage, family, evidence）标签，且通过一致性校验。

## 3. 子环境构建（组合原子 = 语义单元）

### 3.1 拆分动机
直接对文件做随机子集无法还原噪声的"成套"结构：一份伪权威文件只有在**目标正本在场**、配套
审批/邮件/群聊"回声"成套出现时，其诱饵才完整。因此子环境的组合原子不是单文件，而是**语义单元**——
任务噪声设计中真实存在的可拆分结构：
- **攻击场景（attack scene）**：诱饵链完整成员（伪终版/伪权威包/支持文本/回声）+ 其攻击目标 canonical；
- **版本族（version family）**：canonical 与同族被取代版本（含顺序）；
- **指针/诱导组**：redirect 文本、快捷方式、邮件/群聊导出；
- **bulk 组**：状态标记单例或无关文档，做密度填充。

约束（硬规则）：攻击场景**必须包含目标 canonical**（否则"找正本"无解）；诱饵与其支持文本成套出场；
版本族整族出场以保留时间线监督；bulk 只做填充、不单独构成结构。

### 3.2 分批规模与多样性
- **小批 S**：单单元 + 少量填充（4–12 文件）；
- **中批 M**：2–3 单元 + 填充（8–30 文件）；
- **大批 L**：该任务全部强结构单元 + 各类填充代表（上限 80，小任务即全池）；
规模约 S45% / M35% / L20%，正本数量随批次自然变化，避免"恰有一个正本"的捷径先验。

### 3.3 提示（hint）分级
为训练控制难度，定义三级提示：
- **L0**：仅输出要求与概念定义；
- **L1**：加六类类别一行特征 + "标记≠事实"说明（作为部署生产提示，训练主导）；
- **L2**：L1 + 有序核验清单（枚举→标记解析→一致性→权威链→时间线→族聚类）。

对结构丰富任务多分配子环境、结构贫瘠（单场景/纯 bulk）少分配；整体约 **209 个子环境**，覆盖
15 个任务的强结构单元组合，去重保证相同文件集出现 ≤2 次。

### 3.4 泄漏与污染控制
- 训练语料 = manifest 文件子集（不含仓库/答案镜像/真值标签）；
- 部分任务的"答案镜像/可读年报副本"位于角色原始工作区（不在 manifest），构建子环境时按
  机器可读排除清单**物理剔除**，防止模型直接读到答案。

## 4. 教师轨迹（rollout）：用真实读取替代静态拼贴

早期我们把文件内容用轻量解析器（如抽取 docx/xlsx/pdf 文本层）内联进 prompt，进行"静态单轮"生成。
实验发现：**许多 canonical 是扫描件或图片内嵌文档，无文本层**，轻量解析读不到；模型于是系统性把
"读不到内容的正本"误判为噪声（standard 误杀高）。为此 rollout 升级为**工具型 agentic 教师轨迹**：

### 4.1 教师 = Claude Code agent（底层 DeepSeek-V4-Flash）
教师作为 agent 在隔离工作区里，用与真实 Agent 一致的读取工具逐个打开文件：
- 文本/表格/网页用文件读取；
- Office 文档用文档解析/转换（等价于 LibreOffice 等）读取正文与表格；
- 扫描 PDF、图片内嵌文档走 **OCR**。

每个子环境跑出一条 **trace（执行轨迹）**：assistant 分析文本与读取工具的调用、输入输出交错。
SFT 数据即从这些 trace 中构造（见 §6）。

### 4.2 read-fidelity：判别"是否忠实读完全部文件"
由于训练监督建立在教师真实读取之上，引入**判别器**：解析 trace，为工作区每一份文件判断是否被
忠实读取——
- 覆盖性：每个文件至少一次"读取型"工具命中（按路径/命令实参识别，排除目录列举）；
- 忠实性：命中调用的输出需包含该文件的可信内容指纹（对文本文件比对内容片段；对扫描件要求
  OCR 成功且输出非空）。

**只要存在未被忠实读取的文件，该条 trace 即不合格**（不进训练）。判别器在本地与远端两套 rollout
均作为准入门槛，并据其在人工样本上校准"放行全读 trace、拦截漏读 trace"。

### 4.3 OCR 预处理（mock 接口，保持一致性）
在线逐页 OCR 既慢又易被教师跳过（漏读扫描正本）。方案：对训练语料中的少量扫描件做**一次性离线
OCR 预处理**（共 63 个文件 / 约 1100 页，仅涉及 7 个任务），以统一 **OCR 接口**对外提供结果：
- 接口的真实实现 = 与将来部署完全一致的确定性管线（页渲染 + 中文 OCR + 逐页拼接）；
- 训练时该接口直接返回**预处理好的文本**，教师感知不到缓存的存在；
- 因而 trace 中教师"调用 OCR 接口"的返回，与部署时真实执行该管线得到的文本**逐字一致**——
  保证"离线预取"与"在线真跑"行为可迁移，不引入分布偏移。

预处理使扫描 canonical 的读覆盖从"随缘"变为"必得"，并大幅缩短单条 trace 的墙钟时间。

## 5. 确定性评分与保留门槛

对每条 trace 的最终判定做**确定性评分**（无 LLM judge，全部基于标签真值）：
- **划分**：noise 精确率/召回/F1；standard 误杀数（须为 0）；
- **类别**：噪声类别混淆；**强诱饵类别**（hijack_final / fabricated_authority / redirect）须命中；
- **阶段**：stage 准确率（有标注者）；
- **族/时间线**：族级 pairwise 聚类 F1；对含版本族的子环境，已标注 order 上的 Kendall τ 与 canonical 命中；
- **证据**：噪声判定给出非空 evidence 的比例。

**保留（进入 SFT）门槛**：划分 F1 ≥ 0.9 且 standard 零误杀 且 强诱饵类别全中 且（含版本族的
子环境）时间线顺序全对；未达标者先做 hint 升一级重试（≤2 次），仍失败则进入失败分析、不静默丢弃。

## 6. 后训练（SFT，LoRA on 27B）

### 6.1 数据组装
- **主样本**：通过保留门槛的教师 trace。user = 提示（含 hint）+ 工作区文件清单；assistant =
  分析过程 + 工具读取调用 + 最终判定 JSON，构成"普通多轮指令 + 工具调用"的 chat 格式；
- **难度覆盖**：按 hint 级别（L0/L1/L2）与批档（S/M/L）分层，保证简单判别与复杂权威链核验都有样本；
- **样本量不足时扩量**：组合生成成本极低，可低成本再生成补充子环境并跑教师标注，直至主样本足够。

### 6.2 训练
- 基座 **27B**，**LoRA** 轻量后训练（上下文窗口内可直接容纳单条轨迹；超长轨迹截尾保留最终判定）；
- epoch 3–5；按难度代理做简单课程（先易后难）可选；
- 监督信号对齐 §5 的保留判定，使模型在"划分 / 类别 / 时间线"三输出上一致。

### 6.3 评估（held-out）
从 209 个中分层留出 dev 子集（覆盖三批档与三 hint 级，每任务 1–2 个）**不进入训练**：
- 达标线：划分 F1 ≥ 0.85；强诱饵类别准确率 ≥ 0.8；时间线 τ ≥ 0.7；standard 误杀率 ≤ 2%；
- 失败分析：按 category/stage 混淆定位短板，如需要做一轮补训（针对短板类别的 drill）。

## 7. 方法要点总结
1. **任务无关 + 三输出**：划分/类别/时间线，证据全部在文件本身，不依赖任务文本；
2. **语义单元原子**：成套构建攻击场景与版本族，保证"找正本、辨伪链"在子环境内可解；
3. **stage/category 分离**：教模型"不轻信标记、标记需核验"，正是版本/伪权威噪声的核心；
4. **工具型教师 + read-fidelity 门槛**：教师用与部署一致的读取工具（含 OCR 接口）真实读完全部文件，
   无法忠读全文件的 trace 不入训练；
5. **OCR 预处理 = mock 接口**：离线预取、接口与真实管线逐字一致，同时保速度与一致性；
6. **确定性评分 + 拒绝采样**：无 judge 偏差，门槛清晰，失败进分析不静默；
7. **LoRA 后训练小模型**：学到的是可迁移的"文件内在可信度/版本核验"，用于上游工作区过滤。

## 8. 已知边界与未来工作
- 扫描件仍是最贵的数据环节；OCR 质量直接影响 canonical 判断，必要时引入更强文档理解（版面/表格）；
- 无文本与多页文档的 token 预算、以及 agent 长轨迹的上下文截断策略是训练期的工程约束；
- 当前以离线文件语料为主；扩展到跨来源（邮件/群聊/网页）与动作闭环是后续方向。
