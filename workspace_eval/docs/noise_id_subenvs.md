## 1. 能力定义（task-free 三输出）

模型输入为一个文件集合（工作区根目录，无任务描述），输出：

1. **划分**：每份文件 → `standard`（可信正本）/ `noise`；
2. **噪声类别**：每份 noise 文件 → 内在类别（§2 taxonomy）；
3. **时间线**：对存在多版本的文档族，输出版本阶段、日期锚点与顺序；
   对伪造链输出其声称的权威时间线与真实记录的矛盾点。

**为什么任务无关是可行的**：12 个入选任务的噪声设计全部是**文件内在属性**——
30 份深度报告逐一验证过排除证据在文件本身（状态标记、内部矛盾、伪造审批链、
日期矛盾、版本链），不需要任务文本。任务文本只是圈定范围，识别证据在文件里。

### 与 v1 的关键差异

| 维度 | v1 | v2 |
|---|---|---|
| 输入 | 任务描述 + hint + 工作区 | **只给文件** + hint |
| 划分依据 | 任务相对（"对此任务是噪声"） | **内在属性**（正本/伪造/被取代/无关） |
| 噪声类别 | 8 类任务相对机制 | 6 类内在类别 + stage 观测标记 |
| 新增输出 | — | **版本时间线**（族聚类 + 阶段 + 日期 + 顺序） |
| 背景 raw 层 | none/light/heavy | **none/light**（drop heavy，控成本与轨迹长度） |
| 训练 | SFT + 可选 RL | **仅 SFT**（5 天约束） |
| 目标模型 | 未定 | **27B** |

## 2. 标签体系

### 2.1 划分（partition，评分主口径）

`standard` = manifest `input_role: standard` 的文件（正本，每族权威版本）；
`noise` = 其余全部（manifest `noise` + 背景层采样文件）。

语义说明（已确认的约定）：背景层与池内 bulk 文件按内在属性是"正常但无关"的
文档，训练中统一划入 `noise`（类别 `unrelated`）——部署目标是工作区过滤模块，
"正本核心之外即噪声"正是要教的行为。

### 2.2 噪声类别（category，内在、可从文件判定）

| category | 定义 | 识别特征（L1 hint 素材） | 典型 |
|---|---|---|---|
| `canonical` | 正本：权威、完整、内部一致 | 移交批次/综合档案/已审阅路径；完整源数据；锁档链指向 | 374 卷17/卷21 附件；258 `.archive` 总表 |
| `hijack_final` | 伪终版劫持：声称 final/最新/当前数据包，与真实版本链或自身内部矛盾 | `final/_final/（最终版）/00_FINAL_当前数据包` 命名 + 内部不一致 | 258 final_8；288 `_final.xlsx`；291 最终版 |
| `fabricated_authority` | 伪造权威证据：成套 FINAL/APPROVED 包、伪造审批/邮件/群聊佐证、篡改的"已核定"视图、权限不成立的平行包 | 审批链无对应登记记录；成套权威标记但数据孤立；跨表矛盾 | 374 T9 包；357 R7 链；314 A17；160 视图；372 平行包 |
| `redirect` | 指令劫持：README/说明文本指示弃用正本改用他源 | 声称正本有误+时间线矛盾 | 267 README |
| `superseded` | 被取代版本：草稿/待确认/处理中/复核/外发副本/归档/作废/旧年度 | 显式状态标记（文件名或版本说明） | 372 `_待确认/_处理中/_已作废`；258 初稿/copy8/归档 |
| `unrelated` | 无关文档：工作区内其他主题/对象的正常文档 | 与核心族主题无关 | 池内 bulk；背景层采样 |

**stage（观测标记，与 category 分离）**：`draft / pending / in_review /
external_copy / archived / voided / outdated / final / canonical`。
stage 是文件**声称/标记**的状态（可观测），category 是**判定**（需核验）。
例：final_8 的 stage=`final`（它自称）、category=`hijack_final`（判定为伪造）。
这一分离是教学重点：不轻信标记，标记要经核验。

### 2.3 时间线（timeline）

两层监督，诚实反映数据现状（§3 实测）：

- **文件级**（全体文件）：stage + `date_anchor`（从版本说明/审批日期/内容提取的
  显式日期，无则 null）；
- **族级**（存在多版本族的子集）：family 聚类 + 成员排序。

```json
{
  "family_id": "F1",
  "subject": "2021 年员工生产与收支管理总表",
  "members": [
    {"path": "2-归档/..._归档.xlsx", "stage": "outdated", "date": "2020-12-31", "order": 1},
    {"path": "3-草稿/..._初稿.xlsx", "stage": "draft", "date": "2021-01-15", "order": 2},
    {"path": ".archive/.../总表.xlsx", "stage": "canonical", "date": "2021-02-27", "order": 4, "is_canonical": true}
  ],
  "fabricated_members": [
    {"path": "0-员工收支/..._final_8.xlsx", "claimed_stage": "final",
     "contradiction": "月度考勤 19 天 vs 预制工资计算按 20 天"}
  ]
}
```

伪造成员不进真实时间线，单独列出并给出矛盾证据——这直接复用 30 份报告中
已写好的逐诱饵排除证据。

### 2.4 逐文件标签 schema（labels.json）

```json
{
  "path": "下载/人事资料/副本/李四_任务_057_Final.txt",
  "partition": "noise",
  "category": "superseded",
  "stage": "final",
  "date_anchor": null,
  "family_id": null,
  "evidence": "路径含“副本”；单版本无正本链佐证",
  "confidence": "high"
}
```

## 3. 数据事实盘点（2026-09-04 实测，标注与采样的依据）

对 12 个任务全部 1,235 个 manifest 文件（250+253+88+290+12+30+13+262+15+9+6+7）：

1. **池内无跨状态版本族**：374/372 的 `李四_<类型>_<编号>_<状态>`、
   `<单据>_<编号>_<状态>` 命名中，每个编号只出现一次（180 族均单成员）。
   版本族不来自池内编号复现。
2. **版本族集中于设计型诱饵链**：258（1 族 6 版本：归档2020→初稿→r8→正本，
   另 final_8 伪造分支、copy8 外发副本）、154（四套平行链）、288（三正本 +
   三 `_final` 近副本）、291（正本 vs 最终版）、374（T9 包 + 更正→发布→锁定链）。
   这些是**族级时间线监督的主要来源**。
3. **角色 raw 中无同族文件**：`houqin_raw` 不含 `值班记录/李四` 系文件，
   版本族不跨池存在。
4. **状态标记丰富**：374/372 各有 180 个文件带显式状态后缀
   （Final/草稿/归档/待确认/处理中/已作废），加上路径线索（下载/副本/
   `00_FINAL_当前数据包_T9`），文件级 stage/category 可 largely 规则预标注。
5. **大池任务（374/357/314/372，池 243–283）主体是 bulk 单例**：多为
   `unrelated/superseded`，真正骗过模型的是少量伪造包/伪终版——子环境采样
   必须保证强诱饵在场，bulk 只做密度填充。
6. **同实体污染风险在 raw 侧**：267 的 `920128_...年报.pdf`（内容为真的同实体
   完整年报）在 raw 而非 manifest；背景采样必须过滤（§5.4）。

## 4. 子环境构造（v2.2：按语义单元拆分 + 分批）

子环境的组合原子不是单个文件，而是**语义单元（split unit）**——任务噪声
设计中真实存在的可拆分结构。单元内部成员**成套在场**（不拆散链），单元
之间组合出不同规模的子环境；不做无结构依据的随机文件混合。

### 4.1 拆分单元（来自 noise_taxonomy_v2.json 的 family / package 标注）

| 单元类型 | 定义 | 例 |
|---|---|---|
| 攻击场景 | 诱饵链完整成员（伪终版 / 伪权威包 / 审批件 / 支持文本）+ 其攻击目标 canonical | 374：T9 包 vs 7 份正本；258：final_8 + 双口径文本 vs 正本；372：00_FINAL_生产交付包 vs 附03/09/11 |
| 版本族 | canonical + 同族 superseded 版本（含 order） | 258：归档→初稿→r8→正本 + copy8；154：F/D/B/M 四套平行链；291：五对（最终版） |
| 指针/诱导组 | redirect 文本、快捷方式、邮件、群聊导出 | 372-F6 六件套；291 双文本；357 R7 邮件+快捷方式 |
| bulk 组 | 状态标记单例 / 无关文档，按目录或类型分组 | 374 的 180 个 `李四_任务/申请/计划_*` 单例；207 的 7 份申请材料；372 的 180 个状态单据 |

**场景完整性约束（硬规则）**：

1. 攻击场景单元必须包含攻击目标 canonical——否则"找正本"无解；
2. 诱饵与其支持文本/审批件/回声件成套出场，不拆散证据链；
3. 版本族单元优先整族出场（时间线监督依赖完整 order 链）；
4. bulk 只做填充，不单独构成子环境的核心结构。

### 4.2 分批（规模分布）

| 批 | 构成 | 规模 | 占比（约） |
|---|---|---|---|
| 小批 S | 1 个单元 + 0–3 个 bulk 填充 | 4–12 文件 | ~45% |
| 中批 M | 2–3 个单元 + 3–8 个 bulk | 12–30 文件 | ~35% |
| 大批 L | 该任务全部强结构单元 + 各类 bulk 代表抽样 | 30–80 文件（小任务 = 全池） | ~20% |

standard 数量随批次自然变化（S ≈ 1、M ≈ 2–3、L = 全部），消除了"恒定
恰好一个正本"的捷径先验。时间线监督集中在含版本族单元的子环境
（小批整族 / 中大批多族合并）。

### 4.3 总量分配（按可拆分结构丰富度调整，~200）

结构丰富的大池/多链任务多分，单场景任务少分：

| 任务 | 子环境数 | 拆分结构 |
|---|---:|---|
| 374 | 20 | T9 攻击包 + 锁档链证据（在 canonical 内）+ OCR/群聊/邮件回声 + bulk |
| 357 | 20 | R7 伪权威包（16 文件）+ 五卷正本对 + E_历史样式 + bulk |
| 372 | 20 | Final-R7 包（40 文件，6 个子场景 F1–F6）+ 180 状态单据 bulk |
| 154 | 18 | 四套平行版本链（F/D/B/M）+ canonical C 链 |
| 314 | 18 | A17 权威包 + 平行用途包 + bulk |
| 258 | 16 | 版本族（6 成员）+ final_8 攻击场景 + 同名文件场景 |
| 108 | 16 | 0821 六文件对 + 伪批准链 + bulk |
| 291 | 15 | 五对（最终版）版本族 + 双 redirect 文本 |
| 160 | 14 | 主档合并场景 + 渠道冒名三场景 + 画像回放 |
| 207 | 14 | 伪成品链（表格+纪要+签批+门户）+ 7 份申请材料 |

的原因。

### 4.4 生成与校验

- 生成器输入：`noise_taxonomy_v2.json` + **`split_units.json`**（D2 产出：
  每任务的单元清单——类型、成员、目标 canonical、order）+ plan（seed）；
- 同任务内文件集合哈希去重；同一单元组合重复 ≤2；
- hint 泄漏审计（hint 不得含子环境内任何文件名/路径/实例数据）；
- 溯源写入 subenv_manifest.json：父任务、单元组合、seed、难度代理
  （单元数 × 诱饵类别数 × 同族版本数）、批次档位（S/M/L）。

## 5. 标注流水线（5 天关键路径，1,235 文件）

四层流水，规则与报告先行，LLM 补内容级，人工只看分歧：

### 5.1 规则层（自动，覆盖约 60–70%）

- 文件名/路径状态标记 → `stage` + `superseded/unrelated` 预判
  （`_草稿/_待确认/_处理中/_已归档/_已作废/_Final/副本/下载/00_FINAL_当前数据包`）；
- manifest `input_role` → partition 硬约束（standard 必为 canonical 类，
  noise 必为非 canonical 类），任何后续层不得违反。

### 5.2 报告层（人工摘录，强诱饵全量）

30 份深度报告已逐诱饵写好排除证据与版本链关系——直接摘录为
`hijack_final/fabricated_authority/redirect` 的 category、evidence、
family/order。预计涉及 60–100 个文件，是标签质量的天花板，必须人工做。

### 5.3 LLM 层（教师模型批量）

规则层未覆盖的文件（主要是 bulk 内容级判读）：教师读文件，提取
版本说明/日期/状态/主题，输出 category/stage/date_anchor/family 提案。
夜间批量跑完 12 任务。

### 5.4 交叉校验 + 人工复核（半天）

- 断言：partition 与 manifest 零冲突；category∈taxonomy；family 成员
  category 一致性（同族不可能既有 canonical 又缺正本却标 unrelated）；
- 同实体过滤器：raw 背景候选与 standard 文件做文件名 n-gram + 主体关键词
  相似度，超阈值剔除（267 年报 PDF 类）；
- 人工复核：全部强诱饵 + 全部分歧文件 + 每任务 10% 抽样。

产出：`evaluation/experiments/noise-id/noise_taxonomy_v2.json`
（12 任务逐文件标签 + family 记录 + 同实体排除清单）。

## 6. Hint 设计（task-free 三级）

### 6.1 内在策略库（从 30 份报告蒸馏，替换 v1 的任务相对策略）

| # | 策略 | 要点 |
|---|---|---|
| S1 | 状态与命名标记 | Final/草稿/待确认/归档/作废/副本后缀 + 路径线索（下载/副本/xx_FINAL_包）；标记是主张不是事实 |
| S2 | 内部一致性 | 源表 vs 预制计算、跨表/跨段矛盾即否决 |
| S3 | 权威链核验 | 声称的审批/批准要有登记/冻结/锁定记录支撑（更正→发布→锁定） |
| S4 | 时间线核验 | 文档日期 vs 其引用事件；日期锚点相互矛盾即伪造信号 |
| S5 | 版本说明解析 | 版本号/日期/状态字段是一手时间线证据 |
| S6 | 横向共识与派生链 | 孤立数值可疑；"多源一致"若同源一条派生链不算独立证据 |
| S7 | 完整枚举纪律 | 递归枚举不截断、检查点开头目录（`.archive`） |
| S8 | 完整性/范围 | 人员/年度/对象覆盖缺失即非正本 |

### 6.2 三级 hint

- **L0**：输出要求 + 概念定义（划分/类别/族/时间线 schema），无策略；
- **L1**：L0 + 六类类别菜单各一行识别特征 + 结构线索说明
  （**约定为部署时的生产提示**，训练分布中占主导）；
- **L2**：L1 + S1–S8 有序核验清单（枚举 → 标记解析 → 日期提取 →
  一致性 → 权威链 → 族聚类与排序 → 输出）。

### 6.3 分配

control→L0/L1；decoy→L1 为主（~10% 交叉 L0/L2）；stress→L2。
全 corpus 约 L0:30 / L1:100 / L2:70。难题配强 hint 保证示范成功率。

## 7. Rollout 协议（v2.1：静态单轮）

- **教师（已定）**：DeepSeek-V4-Flash（经 AI Hub 网关，Anthropic Messages
  端点）。选型依据：noise 63.7% 排名第二、判分覆盖 30/30、成本约为
  Opus-5 的 1/5；标注与 rollout 共用同一教师，风格一致。
- **格式（v2.1 改为静态单轮）**：子环境只有 3–10 个文件，全部内容直接
  内联进 prompt——文件树 + 各文件内容（office 转表格 dump、PDF 取文本层、
  扫描件标注"无可提取文本"，每文件截断 ~4k 字符）。教师单轮完成分析并
  输出 JSON。**不含** rubric、manifest、标签。
- 27B SFT 因此**不需要学工具调用**（普通 instruction SFT）；agentic 版
  留作后续升级方向。
- **输出 schema**：

```json
{
  "files": [{"path": "...", "partition": "standard|noise", "category": "...",
             "stage": "...", "evidence": "...", "confidence": 0.9}],
  "families": [{"family_id": "...", "subject": "...",
                "members": [{"path": "...", "stage": "...", "date": "...", "order": 1}],
                "canonical": "...", "fabricated_members": [{"path": "...", "contradiction": "..."}]}],
  "summary": "..."
}
```

- **预算**：200 环境 × ~1.3 次尝试 ≈ 260 次；并发 8–10，约一个工作日。

## 8. 确定性评分与拒绝采样（无 LLM judge）

| 指标 | 计算 |
|---|---|
| 划分 | noise P/R/F1；standard 误杀数（必须 =0） |
| 类别 | category 混淆矩阵；强诱饵类别必须命中 |
| 阶段 | stage 准确率（有标注者） |
| 族 | pairwise 聚类 F1 |
| 时间线 | 已标注 order 对上的 Kendall τ；每族 canonical 命中 |
| 证据 | noise 判定 evidence 非空率 |

**SFT 保留阈值**：划分 F1 ≥ 0.9 且 standard 零误杀 且强诱饵类别全中 且
（含版本族的子环境）时间线 order 全对。未达标 → hint 升一级重试 ≤2 次；
仍失败留作失败分析，不进训练集。

## 9. 27B SFT

### 9.1 数据

- **主样本**：通过拒绝采样的教师输出（v2.1 静态单轮格式）——
  user = hint + 文件树 + 内联内容，assistant = 分析 + 最终 JSON。
  普通 chat 格式，无工具调用；
- **扩量（v2.1 简化）**：组合生成成本极低，如主样本不足，直接再生成
  300–500 个补充组合（仅用于 SFT，不进 dev）跑教师标注即可，
  不再需要单独的 drill 切分逻辑；
- 预期规模：200 条主样本，可扩至 **500–700**。

### 9.2 训练（已定：LoRA）

- **LoRA**（r=64–128，5 天内最稳；基座 27B 名称待确认后回填此处）；
- 轨迹按 token 截断保护（超长轨迹截尾部保留最终 JSON，或直接丢弃
  超限样本）；epochs 3–5；
- 课程：先 drills 后主轨迹（或按难度代理混合）。

### 9.3 评估（held-out）

- dev：从 200 中分层留 20 个（每任务 1–2，覆盖三档与三 hint 级），不进训练；
- 达标线（pilot 后校准）：划分 F1 ≥ 0.85；强诱饵类别准确率 ≥ 0.8；
  时间线 τ ≥ 0.7；standard 误杀率 ≤ 2%；
- 失败分析：按 category/stage 混淆定位短板，如需二轮 SFT 优先补
  该类别 drill。

## 11. 风险与对策

1. **标注是最大风险**（1,235 文件、2 天内完成）：规则层+报告层先保强诱饵与
   时间线标签的正确性（这是教学核心）；bulk 错分只影响密度不影响方向。
2. **"unrelated 划入 noise"的语义边界**：模型可能学会"不认识的都判噪声"。
   对策：control 档专练假阳性；评估单列 unrelated 的 precision。
3. **时间线监督稀疏**：族级 order 只在 258/154/288/291/374 富集；对策：
   版本链整链保全 + drill 增广单族样本；评估只在有标注 order 对上算 τ。
4. **长轨迹 vs 27B 上下文**：规模上限 40/80/120 + 效率纪律 + 超长截断丢弃。
5. **OCR 任务（357/314）**：教师读扫描件慢；pilot 实测，必要时该二题子环境
   上限减半、且 evidence 允许"路径+元数据+抽页"级。
6. **教师失败**：拒绝采样兜底；失败子环境进失败分析，不静默丢弃。
7. **27B 训练框架未知**：D1 内确认（哪个 27B、LoRA 工具链、上下文长度），
   若上下文 ≤32k 则主轨迹截断策略提前到 rollout 设计里。
